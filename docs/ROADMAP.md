# Remora — Roadmap

Sprints S11 → S17. Two weeks each. Sprints 7–10 (Timeline v2, drop folder,
PCAP, disk images) are delivered; this roadmap starts from that baseline.

## Decisions locked before S11

| Question | Decision |
|---|---|
| Language | **Hardcoded English.** No i18n framework, no string catalogue. CI gate blocks accented characters in source. |
| Artifact storage | **ECS without Elastic.** DuckDB retained, CSV → Parquet, ECS normalisation layer, `ArtifactStore` abstraction. Elasticsearch/OpenSearch stays a possible later implementation, not a rewrite. |
| S11 scope | CI/CD + Alembic + smoke-test bootstrap in one sprint. |

## Dependency graph

```
S11 SOCLE ──┬── S12 CONVENTIONS + ENGLISH ── S13 DESIGN SYSTEM ── S14 UI ROLLOUT
            │
            ├── S15 INGESTION PIPELINE ── S16 EZ PARSERS
            │
            └── S17 SECURITY & TENANTS
```

`S12 → S13 → S14` is a hard chain. `S15/S16` and `S17` can run in parallel with
the UI chain if capacity allows. Nothing may start before S11 lands.

## S11 — Engineering foundation

**Why first:** there is currently no CI, no tests, no tags, and no migrations.
`backend/app/main.py:67` calls `Base.metadata.create_all()`, which creates
missing tables but never alters existing ones. Any release shipped to an
external user today either breaks their instance or silently loses data. A
release process without migrations is decorative.

### Scope

**Branching model**
- `main` — production. Protected. Tagged releases only, never direct commits.
- `integration` — preprod. Target of every feature branch.
- `feat/*`, `fix/*`, `chore/*`, `docs/*` — unit branches, squash-merged into `integration`.
- `spike/*` — throwaway experiments, never merged.
- Promotion `integration → main` is a merge commit (not squash), which is what
  generates the release and its notes.

**Migrations**
- Introduce Alembic.
- Baseline revision generated from the current schema (`alembic revision --autogenerate` against a fresh DB, then hand-audited).
- An adoption path for existing `create_all` databases: `alembic stamp <baseline>`.
- `create_all()` removed from `main.py`; startup runs `alembic upgrade head`.
- Every model change from S11 onward ships with its migration in the same PR. CI fails a PR that changes `models/` without touching `alembic/versions/`.

**CI (GitHub Actions)**
| Job | Contents |
|---|---|
| `lint` | ruff (backend), eslint (frontend) |
| `typecheck` | mypy (permissive: `--ignore-missing-imports`), `tsc --noEmit` |
| `build` | backend Docker image, `vite build` |
| `test` | pytest, vitest |
| `gates` | English-only gate, migration gate, no-`console.log` gate |

**Test bootstrap** — a safety net, not coverage.
- pytest + `httpx.AsyncClient` against `TestClient`: every router answers (200 authenticated / 401 anonymous). ~34 assertions, mostly generated by iterating `app.routes`.
- Fixtures: in-memory SQLite, one seeded user per role, one seeded case.
- Real unit tests on the two pieces where a silent bug is expensive: `services/rql_parser.py` and `services/ez_detection.py`.
- vitest + React Testing Library: `DataTable`, `Sidebar`, `AuthContext`, one case tab.
- Coverage target: **none**. The gate is "the suite is green", not a percentage.

**Versioning and releases**
- SemVer. Current `1.0.0` in `frontend/package.json` is tagged as the baseline `v1.0.0`.
- Conventional Commits enforced on PR titles (squash-merge means the PR title becomes the commit).
- `release-please` opens a release PR against `main` accumulating everything merged into `integration`; merging it tags, writes `CHANGELOG.md`, and publishes GitHub release notes.
- Version is single-sourced (`backend/app/__version__.py`), surfaced by `GET /api/v1/version` and displayed in the sidebar footer.

**Repository hygiene**
- Branch protection on `main` and `integration`: required checks, no force-push, linear history on `main`.
- `CODEOWNERS`, PR template, `CONTRIBUTING.md`, `SECURITY.md`.

### Exit criteria
- A PR cannot merge into `integration` with a red check.
- A model change without a migration is rejected by CI.
- Merging `integration → main` produces a tag and release notes with no manual step.
- An instance created before S11 upgrades to `head` without data loss (verified on a copy of a real DB).

## S12 — Conventions and English conversion — **delivered**

**Why here:** translating touches *strings*; the redesign touches *markup and
classes*. In this order each file is edited once per concern. In the reverse
order, 25 pages are reworked twice and the fresh layout is at risk. More
importantly, once the English gate is in CI, the entire design system is born
in English.

### Scope

**Documentation split** — `CLAUDE.md` (10 kB monolith) becomes an index over `docs/`:
`ARCHITECTURE.md`, `CONVENTIONS.md`, `UI_PATTERNS.md`, `REPORT_TEMPLATES.md`,
`INGESTION.md`, `DESIGN_BRIEF.md`, `ROADMAP.md`.

**Icon registry** — `frontend/src/ui/icons.ts` exports one domain → lucide icon
map. Today `HardDrive` is used for both *Logs* and *Disk Images*
(`Sidebar.tsx:151-153`) — a direct symptom of icon drift. After this sprint, no
component imports from `lucide-react` directly.

**English conversion**
- UI strings, `HTTPException(detail=...)` messages, comments, docstrings, log lines.
- Volume measured: ~550 accented occurrences across 37 frontend files, ~140 across 18 backend files.
- Case data (case names, analyst notes, report content) is **untouched** — that is user data, not source.
- Report templates stay as they are: they are user-authored YAML/DOCX, so an analyst writes deliverables in whatever language the client needs.

**English gate** — five lines of CI YAML, permanently locking the convention:
```yaml
- name: English-only source
  run: |
    ! grep -rIn "[éèêàùçôîœâêûïëäöüñ]" backend/app frontend/src \
        --include='*.py' --include='*.ts' --include='*.tsx'
```

**Page contract** — every page is documented as `PageShell` with header,
toolbar, content and optional aside in fixed positions. Written down in
`CONVENTIONS.md` before S13 builds the primitive.

### Exit criteria — all met
- `docs/` is authoritative; `CLAUDE.md` contains only pointers.
- The English gate passes on a full repository scan (398 lines converted).
- No direct `lucide-react` import outside `ui/icons.ts`, enforced by eslint.

### Carried forward
| Item | Why it was not done here |
|---|---|
| `B904` — `raise ... from` | 33 sites, each a judgement between `from exc` and `from None`. Applying it blind would either suppress useful causes or chain internal errors into places they do not belong. |
| `@typescript-eslint/no-explicit-any` | ~90 uses, most around ReactFlow and axios error shapes. That is a typing exercise, not a lint pass, and it belongs with the component work in S13/S14. |
| `E701`/`E702`, no formatter | A decision, not a backlog. This codebase column-aligns assignments; Black-style formatting collapses that. Documented in `pyproject.toml`. |
| `fmtDate` returns `13 May 2026` | Section 6 requires the ISO form. Pinned by a test so S13 changes it deliberately rather than by accident. |

## S13 — Design system

**Why the tokens come first:** `tailwind.config.js` holds literal hex values.
`accent-green` is in fact `#2DD4BF` — teal, not green; the token name already
lies. Until colours are CSS variables, dark/light and a GitHub theme are
technically unreachable. This is a prerequisite of the redesign, not a
consequence of it.

### Scope
- Colours moved to semantic CSS variables (`--surface-base`, `--surface-raised`, `--text-primary`, `--accent`, `--border-subtle`, …). Tailwind consumes `var(--…)`. Themes become a `:root` swap.
- Themes: `dark` (current identity, default), `light`, `github-dark`, `github-light`. Theme stored per user server-side, with `localStorage` as the pre-auth fallback.
- Claude Design brief executed (see `DESIGN_BRIEF.md`) → primitives: `PageShell`, `Panel`, `DataTable`, `Toolbar`, `FilterChips`, `SidePanel`, `StatTile`, `EmptyState`, `HelpPopover`.
- Unified chart palette derived from the accent, replacing per-page ad-hoc colours.
- Shared ReactFlow components extracted from the playbook editor (`PlaybookNodes`, `PlaybookEdges`, layout, controls) into `components/graph/` — this is the prerequisite for the attack-graph parity work in S14.

### Exit criteria
- Zero literal hex value outside the token file.
- All four themes render every primitive correctly in a Storybook-style gallery route.
- Primitives are documented in `UI_PATTERNS.md`.

## S14 — UI rollout, responsive, help

**Grouping rationale:** the help system, the responsive pass, the attack-graph
parity and the Explorer detail sidebar all require touching the same pages.
Doing them as separate sprints means walking through 25 pages three times.

### Scope
- Page migration to primitives, in batches: `Cases`/`Dashboard` → `ArtifactExplorer` → artifact pages → configuration pages.
- `ArtifactExplorer.tsx` (2 599 lines) is split during its migration — it is the single largest maintenance risk in the frontend.
- Responsive breakpoints against real hardware: 14″ (1366/1512), 24–27″ (1920/2560), ultrawide 21:9 (3440). **Rule for ultrawide: add a third column, never widen existing columns.** A 2000 px-wide table row is unreadable.
- `HelpPopover` on every page: RQL examples on the Explorer, drop-folder commands on Disk Images, plugin reference on Memory, and so on. Content lives in `frontend/src/help/<page>.tsx`.
- Attack graph rebuilt on the shared graph components extracted in S13, reaching playbook-editor parity.
- Explorer row click opens a wide right-hand `SidePanel` with the full event detail (all columns, raw record, copy-to-clipboard, pin-to-timeline).

### Exit criteria
- Every page renders correctly at 1366, 1920, 2560 and 3440 px wide.
- Every page exposes a `?` with page-specific content.
- The attack graph and the playbook editor share their node/edge implementation.

## S15 — Unified ingestion pipeline

Full specification in `INGESTION.md`.

**The problem being solved:** 14 routers expose `UploadFile`, each with its own
storage layout and its own hashing (or none). There is no single answer to
"what has been ingested into this case, and is it a duplicate?".

### Scope
- `services/ingest/` — a state machine: `discovered → hashed → identified → routed → parsed → indexed`, with `unidentified` and `failed` as terminal-but-recoverable states.
- SHA-256 on every file; magic-byte identification (`python-magic`) taking priority over the extension, so a `.txt` that is really an EVTX is routed correctly.
- `ingested_files` table: the single source of truth for provenance (origin, hash, detected type, routing decision, source timezone, state, error).
- Declarative routing table (see `INGESTION.md`).
- **The drop folder becomes the only ingestion path, reached two ways** (`INGESTION.md` §2): directly on the host (`cp`, `scp`, a mounted share) and from the Collection tab. The tab's upload is a courier - it writes into `.incoming/`, renames the finished file into the case folder, returns `202`, and holds no parsing or storage logic. Unitary import is removed, not deprecated.
- The eight artifact upload endpoints (`binary`, `case_emails`, `collection_import`, `csv_artifacts`, `email_analysis`, `evidences`, `evtx`, `memory`) are consolidated. Platform content - report templates, rule packs, avatars, vault - keeps its own path and is out of scope.
- The Collection tab is rebuilt around the ingest queue: state per file, force a type on `unidentified`, retry a `failed`, set the source timezone before parsing.
- **Source timezone** per collection and per file. The existing `TimezoneContext` is display-only; this adds the missing input side, so mixed local/UTC exports stay coherent.
- `_inbox` reassignment from the Collection tab.
- Storage moves CSV → **Parquet**, partitioned by case and artifact type. Immediate query win with no architectural change: today `read_csv_auto` re-scans the whole file on every request.
- `ArtifactStore` interface (`search`, `aggregate`, `get_by_id`, `schema`) with the DuckDB implementation behind it. This is the abstraction that makes a later Elasticsearch/OpenSearch backend an implementation rather than a rewrite.

### Exit criteria
- Every ingestion path produces an `ingested_files` row.
- The same file dropped twice into one case is rejected as a duplicate, with the original referenced.
- No router contains parsing or storage logic for case artifacts.
- An artifact uploaded from the Collection tab and the same artifact dropped by `scp` produce `ingested_files` rows differing only in `origin` and `origin_detail`.
- A browser upload interrupted mid-request leaves nothing ingestible behind.
- Explorer queries run against `ArtifactStore`, not against `duckdb` directly.

## S16 — Eric Zimmerman parsers and process tree

### Scope
- .NET 9 runtime in the backend image; EZ tools vendored and version-pinned.
- Sandboxed execution: non-root user, no network, wall-clock timeout, output quota. This is the answer to the question that will be asked on announcement day — "does Remora execute anything coming from the drop folder?" — which becomes "yes" the moment these parsers ship.
- `raw → parsed → dual destination` chain: an EVTX lands in Logs *and* its EVTXECmd CSV lands in the Explorer. Same for `$MFT`/MFTECmd, registry hives/RECmd, Amcache, Shimcache, Prefetch, LNK, jump lists, shellbags, SRUM.
- `services/ez_detection.py` upgraded from filename regex to magic bytes plus content sniffing, and fed by the routing table rather than its own pattern list.
- **Process tree** reconstructed where the data allows: EVTX 4688 / Sysmon 1, plus Amcache and Prefetch as corroboration. Rendered with the shared graph components from S13. Orphan processes attach to a synthetic root rather than disappearing.

### Exit criteria
- A raw EVTX dropped into a case folder appears in both Logs and the Explorer without manual action.
- EZ tool execution is verified to have no network access.
- A process tree is produced from a Sysmon-bearing EVTX sample.

## S17 — Security and multi-tenancy

### Scope
- **MFA (TOTP)**: enrolment with QR code, recovery codes, per-role enforcement policy, admin reset.
- **New roles.** Note the design change: `read_only` and `executive` are **not ranks**. `core/deps.py` currently models roles as a linear `ROLE_RANK`, which cannot express "sees everything but writes nothing" or "sees KPIs only". This sprint replaces the rank comparison with an explicit permission set; the existing three roles become named bundles of permissions so behaviour is unchanged.
  - `read_only` — full read, zero write.
  - `executive` — dashboard, KPIs and reports only; no artifact-level access.
- **Client scoping.** The `Client` model already exists. Add `user_clients` association; every case-scoped query filters on the caller's client set. Enforced in a dependency, not per-router, so a forgotten filter is impossible.
- Audit coverage extended to authentication events and permission denials.

### Exit criteria
- A `read_only` user receives 403 on every mutating endpoint (asserted by a generated test over all routes).
- A client-scoped user cannot enumerate or read a case outside their clients, including by direct ID.
- MFA can be required by policy and reset by an admin.

## Deferred, deliberately

| Item | Reason |
|---|---|
| Elasticsearch / OpenSearch backend | Revisit after S15. The `ArtifactStore` interface must exist first, otherwise a spike compares a fresh implementation against eight sprints of accumulated features. Timeboxed to 5 days on `spike/elastic-backend`, with success criteria fixed **before** starting: 10 M EVTX events ingested, filtered query < 500 ms, compose memory footprint < 6 GB, RQL translated to ES DSL for the five most-used operators. One criterion missed ends the spike without debate. |
| Logstash | Not planned in any scenario. SOF-ELK's value is its parsers and ECS mappings, not Logstash. Remora already parses in Python; adding a JVM to perform a bulk POST is free debt. |
| Retention / purge policy | Needed before a public instance runs for a month (disk images and memory dumps are large). Candidate for S18. |
